# Account, settings and reminder fixes — November 17, 2026

Branch: `codex/account-settings-reminder-polish`, based on `origin/dev` at `94b89fd`.
Release metadata: Android/iOS/web 1.0.31 (Android DEV retains its normal `-dev` suffix).

## Approved checklist

1. **Automatic sign-in after verification:** Android's step effect, iOS's step-change handler and the web registration handler cleared the password before the confirmation/login sequence could use it. Preserve only the in-memory registration password during this transition. Back, leaving the form, destruction and success still erase credentials. No password is persisted for this feature.
2. **Notification registration:** remove Device & delivery details and Refresh registration from native settings. Keep the announcement preference and OS-settings link. Existing token-change, authentication-change and foreground registration hooks remain; refresh on entering/resuming the notification settings is automatic. Shorten descriptions in English, Spanish and Polish.
3. **Reminder management:** native reminder rows show the content thumbnail (a fallback when the content has no image), title/content navigation, exact saved time, Edit and Delete. Editing opens the existing native time picker/reminder editor. Web Me also loads the account reminder list and allows editing/deleting those definitions. The browser does not promise native alarm delivery; phone apps reconcile account definitions when active.
4. **Announcements:** the published feed remains public. Guest read/cleared receipts are transferred into the first account signing in on that installation. Claim pending receipts for that identity before network I/O; retain them for retry on failure, without allowing another account to inherit them. Server merges are authenticated, idempotent and scoped to the signed-in profile, using existing tables. Signed-in state remains shared through the existing account receipt endpoints. Signing out returns to the separate guest inbox; it does not expose the previous account's private receipt state.
5. **Android alarm permission:** remove the persistent technical timing warning from prayer/novena detail pages. Explain the optional alarm permission only when setting up a reminder, offer phone settings or Continue, and return to time selection afterward. Android can still delay an alarm if the user declines this OS permission; app code cannot override that restriction.
6. **Settings organization:** clear Account, General, Notifications, Contact & Support and Legal rows. Identity, sign-out and deletion live under Account. Me focuses on saved content, reminders and progress. Preserve Sanctuary branding, native slide navigation, the language bottom sheet and mobile version labels. Remove redundant web profile details.
7. **Immediate progress feedback:** Android previously saved, fetched commitments again, then fetched content metadata before updating the UI. Complete Day now advances local state immediately, saves the known commitment without the redundant read, applies the server result and rolls back on error. iOS follows the same optimistic pattern, with repeated-tap protection, account checks and a visible translated failure. Favoriting renders from the shared optimistic iOS store; stopping a novena updates immediately. Stale collection refreshes cannot overwrite newer progress mutations. The web already advances the day optimistically; its existing flow remains.
